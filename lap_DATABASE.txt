LAPORAN DATABASE APLIKASI INNOBIT
=================================

Tanggal pemeriksaan : 12 Juni 2026
Nama aplikasi       : InnoBit
Framework           : Laravel
DBMS                : MySQL / MariaDB
Nama database       : innobit_laravel
Host                : 127.0.0.1
Port                : 3306
Status migration    : 24 migration sudah dijalankan


1. GAMBARAN UMUM
----------------

Database InnoBit digunakan untuk mendukung website microlearning skill digital.
Data utama yang dikelola meliputi:

1. Akun pengguna dan pembagian peran.
2. Artikel microlearning dan kategori.
3. Proses review serta revisi artikel.
4. Media artikel.
5. Quiz dan hasil pengerjaan quiz.
6. Aktivitas belajar pembaca.
7. Pesan kontak.
8. Aktivitas administratif.
9. Tabel internal Laravel untuk session, cache, queue, dan migration.

Database sudah sesuai dengan fitur aplikasi yang berjalan. Seluruh migration
berstatus Ran dan relasi foreign key utama telah diperiksa.


2. PERAN PENGGUNA
-----------------

Tabel roles menyimpan tiga jenis peran:

1. ADMIN
   - Mengelola seluruh artikel.
   - Menyetujui atau menolak artikel yang dikirim author.
   - Menyetujui atau menolak revisi artikel terbit.
   - Mengelola kategori.
   - Mengelola role dan status akun pengguna.
   - Membaca serta menghapus pesan kontak.
   - Melihat audit log aktivitas administratif.

2. AUTHOR
   - Membuat artikel.
   - Mengedit draft.
   - Mengirim artikel untuk direview admin.
   - Memperbaiki artikel yang ditolak.
   - Mengajukan revisi terhadap artikel yang sudah terbit.
   - Melihat statistik artikel miliknya.

3. USER
   - Membaca artikel yang sudah terbit.
   - Menyimpan artikel sebagai favorit.
   - Menambahkan artikel ke koleksi belajar.
   - Mengerjakan quiz.
   - Memiliki histori dan aktivitas belajar.

Role pengguna direpresentasikan oleh:

- users.role    : nilai enum admin, author, atau user.
- users.role_id : foreign key menuju roles.id.

Kedua kolom dipertahankan untuk kompatibilitas aplikasi. Model User menjaga
sinkronisasi role dan role_id. Hasil pemeriksaan menunjukkan tidak ada data role
yang tidak sinkron.

8. ATURAN FOREIGN KEY
---------------------

CASCADE ON DELETE digunakan untuk data yang tidak lagi relevan ketika induknya
dihapus, misalnya:

- Artikel ketika author atau kategori dihapus.
- Quiz ketika artikel dihapus.
- Pertanyaan ketika quiz dihapus.
- Pilihan jawaban ketika pertanyaan dihapus.
- Favorite dan koleksi ketika user atau artikel dihapus.

SET NULL ON DELETE digunakan ketika riwayat masih perlu dipertahankan, misalnya:

- Reviewer pada article_reviews.
- Reviewer pada article_revisions.
- Pemilik media.
- User pada article_views.
- User pada contact_messages.
- Actor pada audit_logs.
- Thumbnail media pada articles atau article_revisions.

Seluruh foreign key menggunakan CASCADE ON UPDATE.


9. ALUR DATA UTAMA
------------------

A. Registrasi dan login

1. Pengunjung memilih role user atau author.
2. Data akun disimpan di users.
3. role_id menunjuk role yang sesuai.
4. Akun aktif dapat melakukan login.
5. Author wajib menggunakan email mahasiswa Sistem Informasi sesuai validasi
   aplikasi.

B. Publikasi artikel

1. Admin atau author membuat artikel.
2. Artikel author dimulai sebagai draft.
3. Author mengirim artikel sehingga status menjadi review.
4. Admin memberikan keputusan.
5. Keputusan disimpan di article_reviews.
6. Jika disetujui, artikel menjadi published.
7. Jika ditolak, artikel menjadi rejected dan note diberikan kepada author.

C. Revisi artikel terbit

1. Author mengedit artikel published.
2. Versi publik tidak langsung berubah.
3. Calon versi baru disimpan di article_revisions.
4. Admin menyetujui atau menolak revisi.
5. Jika disetujui, data revisi diterapkan ke articles.

D. Proses belajar

1. User membuka artikel published.
2. View dicatat di article_views.
3. User dapat menyimpan favorite atau collection.
4. User mengerjakan quiz.
5. Hasil disimpan di quiz_attempts dan quiz_attempt_answers.

E. Operasional admin

1. Pesan pengunjung disimpan di contact_messages.
2. Admin dapat menandai pesan sudah atau belum dibaca.
3. Aktivitas penting dicatat di audit_logs.

12. VALIDASI INTEGRITAS
-----------------------

Hasil validasi terakhir:

- Semua migration sudah dijalankan.
- Jumlah role sesuai: admin, author, dan user.
- Tidak ada role_id yang tidak memiliki master role.
- Tidak ada perbedaan users.role dengan roles.name.
- Tidak ada referensi ke akun demo lama.
- Tidak ada artikel tanpa author.
- Tidak ada artikel tanpa kategori.
- Tidak ada orphan pada relasi aktivitas belajar utama.
- Email user bersifat unique.
- Slug artikel dan kategori bersifat unique.
- Favorite tidak dapat diduplikasi untuk user dan artikel yang sama.
- Koleksi artikel tidak dapat diduplikasi untuk user dan artikel yang sama.
- Satu artikel hanya memiliki satu quiz utama.


13. CATATAN DESAIN DATABASE
---------------------------

1. Kolom users.role dan users.role_id menyimpan informasi yang sama.
   Hal ini masih aman karena model User melakukan sinkronisasi otomatis.

2. Validasi email author berada pada lapisan aplikasi, bukan constraint database.
   Pendekatan ini sesuai karena aturan email merupakan aturan bisnis registrasi.

3. Status articles menggunakan varchar agar workflow draft, review, published,
   dan rejected dapat berkembang tanpa perubahan enum database.

4. article_revisions memisahkan revisi dari artikel publik sehingga perubahan
   author tidak langsung terlihat pembaca sebelum disetujui admin.

5. Foreign key dan aturan delete sudah mendukung integritas data.

6. Tabel tags sudah tersedia tetapi belum memiliki data pada database lokal.
   Ini bukan error; fitur dapat digunakan ketika tagging artikel diperlukan.


14. KESIMPULAN
--------------

Database InnoBit sudah sesuai untuk kebutuhan website microlearning dengan tiga
peran pengguna, workflow artikel dan approval, quiz, aktivitas belajar, pesan,
serta operasi admin.

Data akun demo ganda telah dirapikan tanpa menghilangkan data terkait. Seluruh
referensi dipindahkan ke akun canonical dan hasil pemeriksaan tidak menemukan
orphan foreign key maupun ketidaksesuaian role.

Database dinyatakan siap digunakan dan siap disertakan dalam pengumpulan
project, dengan catatan file .env dan kredensial produksi tidak boleh dibagikan
ke repository publik.
